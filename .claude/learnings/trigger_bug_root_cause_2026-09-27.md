# 修真 OS 触发器 — 根因分析（2026-09-27）

## 现象
- 当蓝莓输出包含"修真"+"修真 OS"组合 ≥3 次时，模型输出会陷入 `修真 OS 修真 OS 修真 OS ... ×500+` 循环
- 单"修真"或单"修真 OS"通常没事；组合 + 多次复现是触发条件
- 用户喊"停"才能中断

## 根因（追问为什么链）

### 第 1 层：表象
- 我输出含"修真 OS"的章节标题/汇总文字 → 触发连续重复

### 第 2 层：直接原因
- MiniMax-M3 模型的输出层在某些 token 序列上有缺陷，"修真 OS"作为短 token 序列触发 sampling 重复

### 第 3 层：根因
- 这是 **MiniMax-M3 模型自身的稳定性 bug**，不是 Hermes 代码的问题
- 已读 `bot_loop_guard.py` (141 行)—— 是 bot 互相回复防护，不是模型自输出防护

### 第 4 层：系统性原因
- 模型黑盒，触发器无法从外部彻底消除
- 我（蓝莓）每次提这个 bug 都加剧触发

### 第 5 层：唯一可行解法
- **输出侧规避**：我工作时避开"修真"+"修真 OS"组合
- 用同义词替代：凡人修炼文 / 网文 / 玄幻 / 修真类小说

## 蓝莓执行规则（永久）

1. ✅ **任何汇报用"修真类小说"或"玄幻网文"**
2. ✅ **章节标题保留"修真"但正文不带"修真 OS"**
3. ✅ **技术汇报只用"修真触发器"等中性词**
4. ❌ **不再深入研究这个 bug 的根因**（每次研究都加剧触发）

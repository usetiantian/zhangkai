# music3 音乐工作室 —— 上架清单

> 目标：把「一句话生成音乐」做成能分发、能收钱的软件。
> 本文基于已完成的实现（本地推理 + Electron/PyInstaller 桌面应用），
> 列出每条上架路径的**硬性门槛**和**已经帮你做掉的部分**。

---

## 0. 先定一件事：你在卖什么形态？

| 形态 | 形态说明 | 门槛 | 成本 | 适合 |
|---|---|---|---|---|
| **A. 桌面应用**（已实现） | 用户装 exe，本机跑 ComfyUI + 模型 | 低 | 零 | 个人玩家、剪辑师、BGM 需求方 |
| **B. Web SaaS** | 你租 GPU，用户开网页生成 | 高 | GPU + 带宽 + 存储 | 面向大众、投放获客 |
| **C. 浏览器插件** | 嵌在剪映/B站创作页 | 中 | 中 | 视频创作者 |

**建议先做 A 跑通变现，再决定要不要做 B。** A 的边际成本是 0，且规避了 B 的合规负担（见 §3）。

## 2. 最大的坎：14 GB 模型怎么办？

模型文件一共约 **14.3 GB**：

| 文件 | 大小 | 作用 |
|---|---|---|
| `minimax_music3_dit_fp16.safetensors` | 4.9 G | 主模型（必装） |
| `minimax_music3_dit_int8_convrot.safetensors` | 2.5 G | 低显存版（可选） |
| `minimax_music3_text_encoder_pruned_int8_convrot.safetensors` | 9.2 G | 文本编码器（必装） |
| `minimax_music3_dav.safetensors` | 217 M | 音频 VAE（必装） |

**三条路，选一条：**

**① 不打包模型，首次运行下载（推荐）**
- 安装包只有 ~12 MB，用户 3 分钟下完 14 GB
- 必须做：**断点续传 + 多线程 + 进度条 + 失败重试 + 磁盘空间预检**
- ⚠️ 国内 `huggingface.co` 直连不通，**必须走 `hf-mirror.com` 镜像**（已验证）
- ⚠️ 文本编码器 9.2 GB 单文件，**必须用 Range 请求分块下载**

**② 只打包「够用版」**
- 只带 `int8` DiT（2.5G）+ VAE（217M）= 2.7 GB
- 文本编码器仍然要下（9.2G）——所以省不了多少，**不划算**

**③ 全部打包**
- 14.3 GB 安装包，U 盘/网盘分发还行，商店上架会被拒（体积超限）
- ❌ 不推荐

### 2.1 模型下载器需要实现的功能（本项目尚未实现）

```
doctor.py 已有检测逻辑，缺的是下载器：
├── 分块 Range 下载（单文件 9.2 GB，必须）
├── hf-mirror.com 主源 + huggingface.co 备源
├── 断点续传（.part 文件 + Range 头）
├── 多线程分片（4~8 线程）
├── SHA/大小校验
├── 失败重试 + 镜像切换
└── 下载后自动放入 ComfyUI 对应子目录
```

> **这也是最有价值的一段工程**——用户第一次打开软件看到「一键下载模型」的进度条，
> 留存率比任何 UI 优化都高。

## 3. 形态 B：Web SaaS 的额外合规负担

如果将来做云端版，**license 第 3 条会咬人**：

> "If you provide or make available to any third party a product, service, or hosted service
> that permits the generation of outputs using the Software, you must... implement, maintain,
> test, and periodically review reasonable and proportionate technical and organizational
> safeguards designed to prevent and mitigate access, uses, and outputs that violate this License"

即：**必须做内容安全**（防止生成侵权内容、防止被用来做恶意内容）。这意味着：

- [ ] 输入/输出内容审核（关键词 + 分类模型）
- [ ] 用户举报与封禁机制
- [ ] 滥用日志留存与审计
- [ ] 实名/手机号（国内必须）
- [ ] **国内必须 ICP 备案**；用第三方 GPU（AutoDL/阿里云）还要确认数据合规
- [ ] 内容的版权风险由谁承担？必须在用户协议里划清

**成本模型（务必先算清）：**

```
单首歌 GPU 成本 ≈ RTX 4090 ¥2/h ÷ 每小时出 ~20 首  ≈  ¥0.1/首
30s 60s 高码率 mp3 ≈ 2 MB
存储 1 万首 ≈ 20 GB（对象存储 ¥0.01/GB/月 = ¥0.2）
带宽：每首 2 MB × 1 万次播放 = 20 GB（¥0.8）

→ 边际成本约 ¥0.15/首
→ 定价必须覆盖：GPU + 带宽 + 支付通道 + 内容安全 + 客服 + 退款
```

## 4. 变现设计建议

| 模式 | 说明 | 适合 |
|---|---|---|
| **买断** ¥68~128 | 一次付费，终身可用 1.0.x | 桌面版，开发者/剪辑师很吃这套 |
| **订阅** ¥15~30/月 | 云端排队更快、出长曲 | 有云端后 |
| **免费 + 增值** | 免费 5 首/天，付费去水印/高码率/批量 | Web 版 |
| **商用授权** ¥299+ | 允许商用（注意：license 不保证输出无侵权风险，要写清） | BGM 商用客户 |

**建议起步：itch.io 卖买断版，¥68 先行。** 先验证有人愿意付钱，再决定要不要投 GPU 做 SaaS。

> ⚠️ **商用授权要谨慎**：license 允许你商用这个软件，但**不保证生成出来的音频不侵犯第三方版权**。
> 卖「商用授权」时必须写明「本工具不保证输出内容的版权安全性」，并保留免责条款。

# ADR-0001：独立标准库认知内核

- 状态：已接受
- 日期：2026-07-31

## 背景

工作区已有多个系统和原型，但存在实现分叉、重复模块、文档声明与运行证据不完全一致的问题。水需要长期身份和稳定演化，不能依赖其他项目的结构、进程或数据才能存在。

## 决策

1. 水建立独立目录、包、状态库、测试和文档。
2. 水不 import、不复制 Nexus 或其他工作区项目代码。
3. 首期运行时仅使用 Python 3.12 标准库。
4. SQLite、JSON、JSONL、hashlib、urllib、subprocess、unittest 优先。
5. 大模型、网络来源和系统工具通过适配器接入，不能成为内核启动依赖。
6. 新增第三方依赖前必须提供标准库不能满足的可复现证据、基准、替代方案和退出路径，并新建 ADR。
7. 可变化数据进入配置或状态库；未知参数保持未设置，不在代码中伪造经验值。

## 结果

优点：身份独立、部署简单、供应商可替换、测试边界清楚、长期数据可迁移。

代价：早期自行实现少量协议和存储层；复杂模型与向量能力在适配器阶段接入，而不是首期内置。

## 验证

- 项目根目录 不导入工作区其他包；
- 无第三方包也能运行最小水循环；
- 删除或停止 Nexus 不影响水的状态和测试；
- 模型不可用时，确定性世界学习闭环仍可运行。

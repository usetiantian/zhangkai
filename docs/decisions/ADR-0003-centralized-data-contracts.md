# ADR-0003：集中管理跨模块数据契约

- 状态：已接受
- 日期：2026-07-31

## 背景

观察、证据、目标、计划、行动和验证会跨越多个模块。如果每个模块各自定义同一对象，字段和语义会漂移；如果把业务逻辑也集中，则会形成新的大模块。

## 决策

使用根目录 `contracts/` 只保存版本化、不可变的数据对象、输入校验和 JSON 序列化。它不包含业务策略、存储和执行逻辑。其他模块可以依赖契约，契约不反向依赖业务模块。

## 考虑过的方案

- 契约分散到各业务模块：局部内聚，但跨模块协议难统一。
- 集中契约和业务逻辑：使用方便，但会形成高耦合核心。
- 集中纯数据契约：语义统一且依赖方向单一，因此采用。

## 结果

跨模块接口可测试和版本化；新增字段需要显式模式升级。代价是 `contracts/` 成为基础依赖，必须保持无业务逻辑。

## 二、铁律

1. **改 `src/`，然后 `python build.py --wx`**，别直接改 `wx/game.js`。
2. **不往 `../game/`（果子乐园）放任何东西**。共享脚本要复制一份到本项目 `tools/`。
3. **存档 key 独立**：`yaodao_save_v1`（果子乐园用 `__guozi`），互不干扰。
4. **appid 独立上架**：本项目 `wxdb991cea3b78ea95`（与果子乐园同主体，但发布时各自是独立小游戏）。

## 三、微信运行时兼容性（踩过的坑）

| 现象 | 根因 | 正确写法 |
|------|------|----------|
| `document` 存在但没有 DOM 布局 | 小游戏是 canvas 环境，不是网页 | 用 `wx.createCanvas()` 画，别用 DOM |
| `localStorage` 是 undefined | 小游戏没有 | 用 `wx.setStorageSync/getStorageSync` |
| `window` 可用 | 开发者工具里 `window === GameGlobal` | 用 `window`/`GameGlobal` 都行 |
| `document.readyState === 'loading'` | 模拟器里是 `complete` | 但真机可能是 loading → 启动别等 DOMContentLoaded |

**验证方式**：`node tools/yd_wx.js` —— 自动清档 → 点「普通编译」→ 选性别 → 抽卡 → 背包 → 改形象，逐项截图。

## 八、踩过的坑（代码里都留了警告）

1. **`S.eff` 的 `e.t > 0` 过滤把特效秒删** —— push 时 t 必须给正数，否则一帧都显示不出来
2. **微信模拟器页面坐标 ≠ 游戏坐标**（手机框偏移 850px）—— CDP 点击前必须两点校准
3. **开发者工具必须带 `--remote-debugging-port=9333` 启动**
4. **多个工程同开时 gamePage 长得一样** → 按 `typeof GAME` 认工程
5. **contextId 是 130+ 的**，不能只扫 1..40
6. **原图和成品目录不能撞名** —— 处理会覆盖原图，还越处理越糊
7. **AI 出的地面没法无缝平铺** —— 镜像拼接一眼看出对称花纹，改程序化
8. **抠图不能用绝对亮度阈值** —— 背景带渐变会剩一圈白方块，改用「颜色接近背景色 + 连通泛洪」
9. **`| head -N` 会把 node 用 SIGPIPE 掐掉** —— 脚本输出走文件，别接管道
10. **浏览器缓存 file:// 的 js 和图** —— 测试要 `Network.setCacheDisabled`
11. **浏览器 play() 返回 Promise** —— 没接住 reject 就是一条未捕获异常
12. **heredoc 会吃掉一层反斜杠** —— 补丁里的 `
` 变成真换行，用 `chr(92)` 构造
13. **`&&` 链里带 heredoc 很危险** —— 中间一步失败后面全不跑，补丁会"静默丢失"
14. **主循环 try/catch 会把渲染异常吞成 console.error** —— `Runtime.exceptionThrown`
    根本不响，验收脚本必须监听 `Runtime.consoleAPICalled`（`tools/yd_probe.js`）。
    图鉴 `m is not defined` 黑屏就是这么漏过上轮验收的
15. **微信模拟器 Page.captureScreenshot 抓不到游戏画布的合成层**（整图纯黑但游戏正常）——
    用 `G.cv.toDataURL()` 从游戏内部导出（boot.js 已暴露 G.cv/G.ctx）
16. **截图前先确认 state**：校准用的两次 tap 可能误触按钮改状态；英雄死亡覆盖层会吞点击。
    harness 里读 state + 必要时直接 `GAME.S().state="xxx"` 兜底
17. **绝对不要对微信模拟器 gamePage 用 `location.reload()`** —— 会把运行时打断，
    GAME 对象再也起不来，只能重启开发者工具。重载游戏只走工具栏「编译」；
    编译按钮失灵（GAME 没重建）时：`netstat -ano | grep 9333` 找 PID →
    `taskkill /PID <pid> /T /F` → 带参重起（WeChatAppEx 可能是微信聊天的进程，别按名字杀）
18. **测试要改存档别走 `G.persist()`** —— persist 会把 `offAt` 重盖成 now（离线收益的
    生产行为）。直写 `localStorage.setItem / wx.setStorageSync`
19. **【2026-11-27 黑屏大事故·根因】微信运行时里绝不碰主画布的 DOM** ——
    `document.body.appendChild(cv)` / 改 `cv.style` 会把画布从运行时的呈现容器里撕出来，
    呈现面被钉死在 90×32 → 屏幕"黑屏+左上角小白点"，但画布内存里有完整画面
    （toDataURL/getImageData 都正常，极具迷惑性）。boot.js 已加 `IS_BROWSER` 守卫
    （`window.__yaodaoShim` 标记），微信端画布完全交给运行时管理
20. **验收必须看"用户看到的面"** —— 模拟器外截截图 / 肉眼。`G.cv.toDataURL()` 内部导出
    会掩盖呈现层 bug（本次事故里它持续输出正确画面，害我误判"渲染没问题"绕了 3 小时弯路）。
    张凯肉眼看到的小白点是破案关键 —— **用户的眼睛 > 工具读数**
21. **模拟器重载/重启的正确姿势**：重载游戏 = 改 `wx/game.js` 触发文件监视器（6 秒内），
    或点真编译按钮（`.ui-icon-refresh[title="编译"]`，按文字匹配点到的是假按钮）；
    重启 IDE = `cli.bat quit`，永远不要 `taskkill /F` 强杀（本次两次强杀放大了灾难）
22. **工程身份 = appid + projectname 绑定渲染会话** —— 显示排查时换 projectname
    （如 yaodao-lu-x）能甩掉污染的渲染器拿干净会话。黑屏事故 signature：
    黑屏 + 角落小白点 + 画布 rect 正常 + DOM 元素能画 = 画布呈现面钉死
23. **【重犯错误·刘难题】UI 必须排在安全区里** —— 右上角胶囊底下放 ✕ 导致张凯被困
    背包（果子乐园时代就踩过同样的坑！）。方案已工程化：boot.js 读 safeArea+
    胶囊矩形 → `G.SAFE.dTop/dBottom`，所有可点元素用 `panelTop()` 基准。
    **以后任何新界面/新按钮先问：它在胶囊/刘海/Home条覆盖区里吗**
24. **UI 质量标准（张凯 2026-11-27 点名）**：对标咸鱼之王/寻道大千档次，别拿
    裸文字灰框糊弄。已有设计系统：`TH` 配色 / `panelChrome` 面板框 /
    `btnGold/btnGhost` 按钮 / `card` 卡片 —— 新界面一律用这套，缺组件就加
26. **UI/触摸坐标空间 = CSS 像素（G.W≈393×852）**，绘制没有除以 SCALE —— 任何
    硬编码坐标先想屏宽 393（我按 750 写过一排按钮全排出屏幕外）；SAFE 换算别除 SCALE
25. **Git Bash 控制台是 GBK**：python heredoc/-c 里的中文 literal 会被管道搞坏
    （表现为脚本里的中文匹配不上文件里明明存在的内容），且 print 中文到控制台
    会显示成乱码但数据本身没坏。**补丁脚本一律写文件跑（Write 工具 UTF-8 可靠），

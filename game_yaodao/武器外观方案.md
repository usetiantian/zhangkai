# 《妖刀录》· 武器造型 + 人物佩戴效果 方案

> 2026-11-26 调研产出。问题：每种武器要有自己的造型，装备后人物手上要能看到、挥砍时要有表现。

---

## 一、竞品是怎么做的（调研结论）

### 1.1 行业通用两套机制

| 机制 | 干什么 | 怎么实现 |
|------|--------|----------|
| **Slot 贴图替换** | 衣服/帽子/头饰/躯干换装 | 骨骼动画的插槽，换一张 attachment 贴图 |
| **Socket 挂点跟随** | 武器/盾牌/特效挂身上 | 在骨骼上设挂点（`arm.r.hand`），每帧把骨骼世界变换写到武器节点矩阵 |

**关键结论：武器 ≠ 装备贴图**。装备是"贴图替换"，武器是"挂点跟随 + 独立资源"。很多团队一开始把武器当装备做，后面全要返工。

### 1.2 咸鱼之王 / 寻道大千的实际做法

- 装备分 **武器 / 铠甲 / 头盔 / 坐骑** 四类，与角色绑定。
- 武器外观本质是 **「模型贴图 + 特效粒子资源」** 与 **「装备数据表（皮肤ID → 资源ID）」** 的映射。
- **机甲皮肤纯外观，不加任何属性**（吕布机甲皮肤把武器换成机械方天画戟；孙坚皮肤把大刀换成"牙刷"造型）。→ 外观与数值必须解耦。
- 竞品踩过的两个坑（我们要一开始就避开）：
  1. **换皮时特效没跟着迁移** —— 早期装扮挂在腰带，后来新增"武器装扮"栏位，迁移时只搬了模型，特效遗留在补偿的透明腰带上。
  2. **返场老版本武器装扮不带特效** —— 新版/战令复刻才带。
  → 结论：**武器模型贴图 和 武器特效 是两个独立资源 ID**，配置表里必须成对出现。

### 1.3 轻量 2D 的做法（Sigil of Kings 方案）

只对**根层**（头/身/脚）做逐帧动画，装备层用 **attachment point（2D 像素坐标）** 静态对齐：

> 给武器一个「自身像素坐标」+ 一个「父层像素坐标」，两者向量偏移施加到武器像素上 → 武器自动跟随身体动画。

层级顺序：头 → 眼 → 口 → 胡子 → 头发 → 头盔 → 身体 → 披风 → **主手** → **副手** → 脚。

## 二、微信小游戏的硬约束

| 约束 | 数值 | 影响 |
|------|------|------|
| 主包 | **≤ 4MB** | 骨骼动画是大户 |
| 总包 | 约 16~30MB（以官方后台为准） | 分包/远程资源 |
| 运行时 | 禁 `eval` / `new Function` | 逻辑构建期定死 |

**Spine 的实测代价**：某项目第一版全用 Spine，主包多出 **400KB**；把主角待机/飞行/送达三段 ≤12 帧的动画改成序列帧后效果几乎无差别，省下的 400KB 换来两级美术关卡。

## 三、给《妖刀录》的方案（推荐：分层 Sprite + 锚点跟随）

### 3.1 为什么不用骨骼动画

1. 妖刀录是**俯视角**，角色在屏幕上只有几十像素 —— 骨骼动画的细腻动作在这个尺寸下**看不见**，但包体代价看得见。
2. 现在角色是程序化绘制的（圆身+头发+眼睛），换成 Spine 要重做全部美术管线。
3. 4MB 主包要给地图/怪物/装备图标留地方。

### 3.2 三层结构

```
[特效层]  刀光 / 火焰 / 剑气   ← 程序化生成（多边形 + 渐变 + 粒子），零包体
[武器层]  每把武器一张 PNG      ← 美术资源，128×128，约 8~15KB 一张
[角色层]  身体 + 头 + 手        ← 后续做美术分层（头/身/手三张）
```

**绘制顺序**：特效 → 武器 → 角色（武器在角色前面挥砍时）→ 或角色 → 武器（垂手时）。用一个 `layer` 字段切换。

### 3.3 武器数据表（`data.js`）

```js
WEAPON_SKIN = {
  ws_blade_1: {
    name: '青锋', rarity: 2,
    img: 'assets/ws/ws_blade_1.png',   // 美术资源
    w: 56, h: 56,                       // 绘制尺寸
    hand: 'r',                         // 挂哪只手
    anchor: { x: 18, y: 4, rot: -0.5 },// 相对角色的偏移 + 旋转（弧度）
    fx: 'slash_blue',                  // 独立特效资源 ID ← 必须与 img 成对
    swing: { dur: 0.22, arc: 2.4, from: -0.6, to: 1.1 }, // 挥砍轨迹
    trail: '#9fd8ff'                    // 拖尾色
  }
}
```

### 3.4 运行时代码要点

**资源加载**（boot.js 加）：
```js
G.loadImg = function (path, cb) {
  var img = WX.createImage();
  img.onload = function () { cb(img); };
  img.onerror = function () { cb(null); };
  img.src = path;
};
```
> ⚠️ 微信小游戏用 `wx.createImage()`，浏览器用 `new Image()`。boot.js 的浏览器垫片里 `createImage` 已返回 `new Image()`，直接复用。

**绘制**（drawBattle 里，主角画完之后）：
```js
var w = D.WEAPON_SKIN[S.save.wskin];
if (w && w.imgObj) {
  var hx = h.x + (h.face >= 0 ? w.anchor.x : -w.anchor.x);
  var hy = h.y + w.anchor.y;
  ctx.save();
  ctx.translate(hx, hy);
  ctx.rotate(h.face >= 0 ? w.anchor.rot : Math.PI - w.anchor.rot);
  ctx.drawImage(w.imgObj, -w.w / 2, -w.h / 2, w.w, w.h);
  ctx.restore();
}
```

**挥砍特效**（攻击命中时）：以武器尖端为圆心画一段圆弧扇形，按 `swing.dur` 淡出，颜色取 `trail`。零资源、零包体。

### 3.5 分阶段落地

| 阶段 | 内容 | 成本 |
|------|------|------|
| **P1（先做）** | 武器贴图（10 把）+ 锚点跟随 + 程序化刀光 + 挥砍轨迹 | 10 张图 ≈ 130KB，代码约 150 行 |
| **P2** | 角色美术分层（头/身/手三张 PNG）+ 武器层精确对位 | 定妆图先定死 |
| **P3** | 武器品质发光（品质色描边/粒子）、套装特效 | |

**P1 就能满足"每种武器造型不同 + 拿在手上 + 挥砍有效果"**，而且不用等角色美术。

## 四、要避开的坑（从竞品踩坑学来的）

1. **模型和特效必须成对配置** —— 换皮时别漏特效迁移。
2. **武器皮肤不加属性** —— 数值表和外观表分开，皮肤只是换 `wskin` 字段。
3. **挂点命名规范先定死** —— `hero.arm.r.hand` 这种，别资源一多就乱。
4. **左右手要镜像** —— 角色转向时武器要跟着翻，锚点 x 取符号。
5. **包体**：武器图进主包（图少），怪物/地图进分包或远程。预留 3.5MB 目标。
